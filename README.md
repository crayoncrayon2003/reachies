# りーち～ず

「reach」と「ちーず」を合わせた、あと一歩足を延ばすためのアプリです。

関西の鉄道路線を地図に重ね、利用する駅を複数選び、駅から行けるイベントを探し、複数の駅・イベントを自由な順番で組み合わせる静的Webアプリです。鉄道で移動できる駅を足掛かりに、駅から徒歩だけでは届かない範囲を捉えます。

公開サイト：[りーち～ず](https://crayoncrayon2003.github.io/reachies/)

[公共交通オープンデータチャレンジ2026](https://challenge2026.odpt.org/)に向けたアプリです。

## 使い方

1. 太い鉄道路線上の大きな駅マークをクリックし、利用する駅を1つ以上選びます。駅名一覧からも選べます。
2. 移動手段を「自転車」「徒歩」から選び、時間を5〜30分で指定します。同じ時間でも手段によって到達圏が変わります。旅程の徒歩・自転車の**各区間**にもこの時間上限を使います。
3. 到達圏は選択駅から片道で行ける範囲です。1駅でも赤色を表示し、駅を増やすとその駅からの到達圏が加わります。
4. 選択した手段・時間に応じた赤色の到達圏と対象イベント数を確認します。
5. 「旅程」で出発駅・到着駅を確認します。選択駅の最初・最後が初期設定され、1駅なら同じ駅への往復です。専用欄で別の駅に変更できます。駅・バス停・イベントのポップアップで追加位置を選びます。駅・バス停は出発地・到着地への設定も可能です。上下ボタンで経由順序を変更し、区間ごとに徒歩・自転車・公共交通を選べます。
6. イベントをクリックすると、選択駅からの移動時間を確認できます。「この組み合わせで旅程を作る」で地点列へ取り込みます。地図の旅程線は接続イメージで、実際の道路経路ではありません。

関西2府4県と周辺（福井・三重方面等）の180路線グループを、国土数値情報2025年度版の線路形状で表示します。南海、地方私鉄、地下鉄、新交通、ケーブル、新幹線も含みます。「関西全体」で全体へ移動できます。表示範囲内の鉄道2,041駅とバス停32,320地点を選択できます。地方駅も丸で表示し、駅・バス停を到達圏の起点と旅程の端点・経由地点に使用できます。到達時間は直線距離と移動速度から推定します。収録状況は [docs/network-coverage.md](docs/network-coverage.md) を参照してください。

**鉄道路線と駅の位置は国土数値情報2025年度版に基づきます。収録イベントは架空で、所要時間は直線距離に基づく推定です。到達圏は実道路のアイソクロンではありません。**路線・会社をまたぐ同一駅は1つの丸に統合しています。大阪・梅田、なんば、三宮も乗換拠点としてまとめます。駅一覧と旅程の候補も同じ統合地点を使います。

計算方法と出典はアプリ内の「データについて」でも確認できます。

## 起動

Node.js 22.12以上（22系推奨）を使います。

```bash
git clone https://github.com/crayoncrayon2003/reachies.git
cd reachies
npm ci
npm run dev
```

WebアプリにはPythonパッケージは不要です。背景地図のOpenStreetMapには通信が必要です。サーバAPIはなく、静的データをブラウザで読み込みます。

## 到達圏とイベントの判定

選択駅集合を S、選択時間を T とします。赤色範囲は、いずれかの駅 A ∈ S から t(A → x) ≤ T で届く場所の和集合です。1駅・複数駅とも同じ判定を使います。駅が0個なら対象イベントは0件です。イベントの候補駅は選択手段で最短の往路時間を持つ駅です。

到達圏の距離換算は川・橋・道路の通行可否を考慮しません。

- 徒歩・自転車のどちらも選択した時間の到達圏を表示します。
- 自転車選択時の到達可能イベントは緑、徒歩選択時は青、条件外は灰色です。
- 鉄道の出発地から選択駅までの時間・乗換・列車運行は計算していません。利用できる駅をユーザーが選ぶ方式です。
- 自転車のポート・在庫・別ポート返却、イベント終了後の列車、天候、バリアフリーは未判定です。所要時間にはイベント滞在を含みません。

## 複数地点の旅程

出発駅・到着駅は地図の選択駅から初期設定します。作成済みの旅程は、到達圏用の駅選択だけでは変更されません。出発地・到着地は専用欄やポップアップから変更できます。地点の追加・削除・並べ替え、区間の移動手段変更ができます。駅・バス停・イベントのポップアップでは「1と2の間」「2と3の間」のように旅程の番号で追加位置を選べて、「旅程から削除」で取り消せます。同じイベントを複数回追加した場合は、削除する箇所を選択できます。未追加のイベントでは削除ボタンは無効です。駅・バス停は旅程編集の地点検索から選び、出発駅・到着駅としての設定、または任意の経由位置への挿入ができます。駅ペアの詳細から旅程の作成も可能です。各区間の時間上限を個別に判定し、全行程の合計時間上限は設定しません。自動で最適な訪問順序を探索する機能ではありません。

駅・イベントの個数は固定せず、隣り合う全地点を順番に結びます。駅A→イベント→駅A、駅A→イベント→駅B、駅A→イベント→イベント→駅A/B、駅A→イベント→駅B→イベント→駅Cなどに対応します。訪問の重複も保持します。同じ座標の訪問番号をまとめ、線上に区間番号（1→2など）を表示して往復を区別します。候補イベントをクリックしても編集中の旅程線は置き換わりません。

始点と終点は公共交通の駅・停留所専用の選択欄で指定します。イベントを端点にはできません。イベントと経由駅は、その間の地点列として追加・削除・並べ替えます。端点が未指定の場合は指定を促し、イベントだけの接続線は表示しません。端点を設定すると保留していた経由地点も含めて全区間を表示します。時間未計算の区間も接続線は描きます。データの地点種別 `station`・`stop`・`bus_stop` を公共交通の端点として扱います。鉄道2,041駅と公式資料のバス停32,320地点を共通の地点として扱います。名称・会社名で検索できます。旅程の候補は先頭150件まで表示し、検索で全地点にアクセスできます。

新規の旅程区間は選択中の移動手段を初期値にします。既存区間の手段は保持し、区間ごとに変更できます。徒歩・自転車とも時間スライダーの上限で判定します。

徒歩・自転車の移動時間は地点間の距離換算です。公共交通は駅・停留所間で指定できますが、時刻表・接続関係を計算していないため「時間未計算」とし、旅程全体が実行可能とは判定しません。実道路データへ差し替えた場合、保存済みの駅→イベント／イベント→駅のみ評価でき、イベント間など未計算の区間は未計算のまま表示します。旅程線は接続イメージです。イベントの開催時間・滞在・終電・貸出返却は判定に含みません。

## 地図の記号と色

駅は丸、イベントは種類ごとのSVG絵記号を持つ角形ピンです。音楽・マーケット・映画・自然・体験・まち歩き・アートを区別します。未知の種類は星を表示します。イベントの `category` を変更すると記号も切り替わり、地図と一覧で共通の記号を使います。ピンの色は到達可否を表します。

到達圏は、選択した移動手段での最短往路所要時間で、5・10・15・20・25・30分以内の6段階に分けます。近いほど濃い赤、遠いほど白に近い赤です。色の基準は時間上限を変えても固定です。色は最寄り選択駅からの往路時間を表し、往復合計や距離kmではありません。

鉄道・バスとも同じ運営会社は全路線を同じ色に統一しています。法人表記の違いを正規化し、京都市・神戸市の地下鉄と市バスも共通の色です。路線凡例は事業者別です。駅・バス停の丸は通常14px、複数路線がある地点は20pxです。元データの会社・路線の組み合わせを重複除去して判定し、同じ路線の複数レコードで大きくはしません。選択やズームではサイズを変えず、選択状態は緑色で示します。駅の丸は常に駅の座標に固定し、画面上の位置を手動でずらしません。駅・バス停の丸をクリックすると、その地点の選択・解除を直接切り替えます。駅のクリック時には、イベントと共通の旅程追加・削除ポップアップを表示します。ズームアニメーション中も丸の画面上の直径を14px／20pxで維持します。クリック領域は32px四方です。ズーム15未満では未選択のバス停を画面上の32px格子につき1地点に間引き、拡大すると全地点を表示します。選択済みの地点は間引かず、検索からは全地点を選べます。駅名が重なる場合は一部の名称を隠し、ホバーまたはキーボードフォーカスで表示します。駅名一覧からも選択できます。

## 静的データ

| ファイル | 内容 |
| --- | --- |
| `public/data/railway.json` | `schema_version: 2`、`stations`、`default_stations`、路線のGeoJSON `lines` |
| `public/data/station_access.json` | `schema_version: 2`、`sample`、距離換算の `model`、`cell_size`、`max_minutes`、格子の `cells` |
| `public/data/bus_routes.geojson` | 事業者別のバス経路と出典 |
| `public/data/bus_stops.json` | P11-22から取得したバス停、会社・元データの記録、出典 |
| `public/data/station_events.geojson` | イベントのPoint FeatureCollection |

座標はWGS84の `[経度, 緯度]` です。駅は `id, name, lon, lat` を持ちます。格子は `id, lon, lat, access` を持ち、経緯度はセル中心です。セル寸法は `cell_size` に保存します。格子は約500mです。距離換算（`model.kind: radial-demo`）では `cells` は空配列で、格子を配信・描画せず、各画面位置の駅からの距離と選択した速度で赤色を描きます。同じ20分でも自転車15km/hでは半径5km、徒歩4.5km/hでは半径1.5kmです。実道路の事前計算データは格子で表示します。イベントはセルの値を流用せず、イベント地点への時間で判定します。

格子・イベントの `access` は駅IDをキーとする次の方向別コストです。到達不能・計算範囲外は `null` または駅キー省略です。

```json
{"osaka": {"out": 12, "back": 14, "walk_out": 35, "walk_back": 38}}
```

`out` は駅から場所への自転車時間、`back` は場所から駅への自転車時間、`walk_out` / `walk_back` は徒歩です。イベントのpropertiesには `id, name, venue, category, date, start, end, fictional, access` を保存します。

距離換算データの再生成にはPythonを使用します。データ処理用の仮想環境を作成します。

```bash
python3 -m venv env
```

再生成コマンド：

```bash
env/bin/python scripts/generate_station_sample.py
```

`railway.json`、`station_access.json`、`station_events.geojson` を更新します。取り込み済みの鉄道形状・駅座標は保持し、その駅を起点として距離換算の所要時間を再生成します。球面距離（地球半径6,371,008.8m）、自転車15km/h、徒歩4.5km/hを共通に使い、選択手段の赤色範囲・イベント判定・旅程の区間時間を揃えています。河川・道路・坂などは反映せず、実道路の到達圏は一般に円にはなりません。`generate_station_sample.py` は `public/data/events.geojson` をイベント情報の入力として使用します。

## 実際の鉄道形状の取り込み

国土交通省の [国土数値情報・鉄道データ2025年度版](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html)（基準日2025-12-31、CC BY 4.0）を使用しています。JR・私鉄・地下鉄を事業者と路線名で抽出し、経度134.15〜136.90、緯度33.35〜35.85の範囲で切り出しました。境界で路線が途切れる場合があります。

4,964区間・75,757頂点を180個のMultiLineStringにまとめています。元の曲線頂点は簡略化せず、離れた区間を直線で接続しません。Leaflet側の線形簡略化も無効です。JGD2011（EPSG:6668）からWGS84（EPSG:4326）への変換にはpyprojを使っています。変換器が報告する精度は1mです。

駅はN02の駅グループコードを基本に統合し、500m以内の同名駅をまとめます。大阪・梅田／なんば／三宮は明示的な名称対応と900m以内の条件でまとめます。遠隔地の同名駅は統合しません。代表点は元の駅区間の中点を所属路線へ投影し、既存の代表駅座標は保持しています。グループ内の各会社・路線・駅位置は `members` に残し、旧IDの対応は `station_aliases` に記録します。取り込み結果と補正量は [docs/railway-import-report.json](docs/railway-import-report.json)、出典・利用条件・取得ZIPのSHA-256は `railway.json` の `provenance` に記録しています。駅マークもこの座標に固定します。

```bash
env/bin/python -m pip install -r requirements-data.txt
# 公式ページから取得した N02-25_GML.zip を inputs/ に保存
env/bin/python scripts/import_railway.py inputs/N02-25_GML.zip
env/bin/python scripts/generate_station_sample.py
npm test
npm run build
```

取得したZIPは `inputs/` に保存してください。このディレクトリはGit管理対象外です。再取り込み時も元の駅IDを保持します。

このデータは表示用の線形であり、列車運行を含む経路探索グラフではありません。全ての線路交差を乗換・分岐とみなすことはできず、経路探索には接続関係とGTFS等の運行情報を別途組み合わせる必要があります。また、縮尺や作成時点が異なる背景地図との完全な画素一致は保証しません。

## バスの経路表示

「地図の表示」は常時表示です。鉄道路線とバス路線を別々にまとめ、鉄道は個別路線、バスは事業者ごとに切り替えます。現在のバス経路原典には系統別の形状がないため、系統別切替は未対応です。駅とバス停留所はそれぞれ独立して表示を切り替えられます。全項目の初期値はONです。初期ズームは14、初期選択は大阪・梅田と京橋の2駅です。路線色は鉄道・バスとも運営会社ごとに統一しています。初回に経路データを読み込み、再表示時は再利用します。現在のデータは約18MB（圧縮前）です。線にマウスを重ねると事業者名が表示されます。

[国土数値情報・バスルート2022年度版](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N07-2022.html)の滋賀・京都・大阪・兵庫・奈良・和歌山・福井・三重を取り込み、上記矩形で切り出しています。219事業者・自治体、45,772区間です。系統別の運行経路ではなく事業者単位の道路経路で、高速バスは整備対象外です。空港リムジンや八木新宮特急など、個別系統との対応も未照合です。2026年現在の運行を示すデータではありません。バスの乗車時間は未計算です。バス停は別途取得した位置データを使い、そこからの徒歩・自転車到達圏を距離換算で表示します。

```bash
env/bin/python scripts/import_bus.py inputs/N07-22_18_SHP.zip inputs/N07-22_24_SHP.zip inputs/N07-22_25_SHP.zip inputs/N07-22_26_SHP.zip inputs/N07-22_27_SHP.zip inputs/N07-22_28_SHP.zip inputs/N07-22_29_SHP.zip inputs/N07-22_30_SHP.zip
```

出力は `public/data/bus_routes.geojson`、事業者一覧・出典・取得ファイルのハッシュは `docs/bus-import-report.json` です。元ZIPの保存先は `inputs/` です。ライセンスはCC BY 4.0、座標はJGD2011からWGS84へ変換しています。

## バス停留所の取り込み

[国土数値情報・バス停留所2022年度版](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-P11-2022.html)の福井・三重・滋賀・京都・大阪・兵庫・奈良・和歌山を使用しています。範囲内の36,619レコードを、同名かつ代表点から100m以内という条件で32,320地点にまとめました。元の会社名・系統名・座標は `members` に保持します。高速バス・デマンドバスは原典の対象外で、現行の運行状況は未確認です。

```bash
env/bin/python scripts/import_bus_stops.py inputs/P11-22_*_GML.zip
```

出力は `public/data/bus_stops.json`、出典・ZIPのハッシュ・件数は `docs/bus-stops-import-report.json` です。CC BY 4.0、JGD2011からWGS84へ変換しています。地図内の駅・バス停はDOMマーカーで描画します。拡大や移動で表示を更新します。選択地点は緑色になり、名前を確認できます。画面外の地点も検索・旅程選択には使えます。

## 実道路の到達圏を事前計算する

`scripts/precompute.py` はr5pyで **駅→格子／イベント、格子／イベント→駅** の自転車・徒歩の計4行列を個別に計算し、同じ3ファイルを出力します。一方通行などで往路・復路が異なる場合も、同じ値と仮定しません。

対象駅とイベントを含むOSM PBF、Java、[r5pyの実行環境](https://r5py.readthedocs.io/stable/user-guide/installation.html)を用意してください。

```bash
env/bin/python -m pip install -r requirements-routing.txt
env/bin/python scripts/precompute.py \
  --osm inputs/kansai.osm.pbf \
  --railway public/data/railway.json \
  --events public/data/station_events.geojson \
  --output computed-data
```

速度設定は自転車15km/h、徒歩4.5km/h、計算上限30分です。駅周辺約7kmの格子を使用します。イベントは独立に計算します。APIは [r5py TravelTimeMatrix](https://r5py.readthedocs.io/stable/reference/reference.html) を使用します。

配信中のデータは距離換算であり、実道路計算の結果は含みません。計算結果と元データの利用条件を確認した後、出力した3ファイルを `public/data/` に配置します。実際のイベント情報を登録する場合は、`fictional` と出典も更新します。

この計算は駅以降の徒歩・自転車移動が対象です。GTFSによる列車・バスの運行やGBFSによる自転車の貸出返却は計算対象に含みません。

## 検証と公開

```bash
npm test
env/bin/python -m unittest discover -s tests -p 'test_*.py'
npm run build
npm run test:browser
npm run preview
```

ブラウザテストはGoogle Chromeを使用します。実行パスは `CHROME_PATH=/path/to/chrome` で指定できます。駅選択・解除、空選択、1駅、方向別駅ペア、時間・モード切替、イベント経由表示、モバイル、読み込み失敗、リポジトリ配下の相対パスを検証します。
