# 公共交通オープンデータチャレンジ2026向けプロジェクト指示書

## コンテストの内容

「公共交通オープンデータチャレンジ2026」は、公共交通オープンデータを活用したアプリケーションコンテストである。

対象となる公共交通データは、鉄道、バス、デマンド交通、航空、フェリー、シェアサイクルなどである。  
少子高齢化、交通空白、オーバーツーリズム、バリアフリー対応など、地域の移動課題に対して、公共交通オープンデータを組み合わせた新しいサービスを提案することが求められている。

本プロジェクトでは、公共交通を単なる移動手段ではなく、地域イベント・観光・生活活動に参加するための社会インフラとして扱う。

参考:

- https://challenge2026.odpt.org/
- https://challenge2026.odpt.org/ja/outline.html
- https://challenge2026.odpt.org/ja/opendata.html

## プロジェクトの内容

プロジェクト名は仮に **「車なしイベントマップ」** とする。

本アプリは、公共交通とレンタサイクルを組み合わせた到達圏を可視化し、その範囲内にある公開イベントを地図上に重ねて表示するWebアプリである。

主題は次の通り。

> 公共交通とレンタサイクルを使うことで、車を使わずにどの地域イベントへ参加できるかを可視化する。

単なる乗換案内ではなく、次の問いに答えるアプリにする。

> このイベントは、車がなくても本当に行けるのか？

### 基本機能

- 大阪周辺を対象にする
- 地図上に公共交通の到達圏を表示する
- 「公共交通のみ」と「公共交通 + レンタサイクル」を比較できるようにする
- 公開イベントを地図上にピン表示する
- イベントごとに、車なしで到達可能かを表示する
- GitHub Pagesで公開できる静的Webアプリとして作る
- サーバAPIは作らない
- 重い到達圏計算はローカルで事前計算し、公開アプリでは静的データを読み込む

### 表示モード

最低限、以下の表示切替を実装する。

- 公共交通のみ
- 公共交通 + 徒歩
- 公共交通 + レンタサイクル

### イベントピンの分類

イベントピンは、到達可能性に応じて色分けする。

- 青: 公共交通だけで行ける
- 緑: レンタサイクル併用で行ける
- 黄: 行けるが帰りが厳しい
- 赤: 車なしでは厳しい

## プロジェクトのdebug方法

### 1. ローカル起動

Viteなどの軽量な静的サイト開発環境を使う。

```bash
npm install
npm run dev
```

ブラウザでローカルURLを開き、以下を確認する。

- 地図が表示される
- 到達圏GeoJSONが読み込まれる
- イベントピンが表示される
- 表示モード切替でレイヤーが変わる
- コンソールにエラーが出ていない

### 2. データ読み込み確認

ブラウザの開発者ツールで以下を確認する。

- `reach_transit.geojson` が200で取得できる
- `reach_transit_walk.geojson` が200で取得できる
- `reach_transit_bike.geojson` が200で取得できる
- `events.geojson` が200で取得できる
- GeoJSONの座標順が `[longitude, latitude]` になっている

### 3. 地図表示確認

以下を確認する。

- 大阪周辺が初期表示される
- ヒートマップが意図した位置に表示される
- イベントピンが大阪周辺に表示される
- レイヤー切替時に古いレイヤーが残らない
- モバイル幅でもUIが崩れない

### 4. GitHub Pages想定確認

GitHub Pagesではルートパスがリポジトリ名配下になる場合がある。  
そのため、データ読み込みパスは絶対パスではなく相対パスを使う。

良い例:

```javascript
fetch("./data/events.geojson")
```

避ける例:

```javascript
fetch("/data/events.geojson")
```

### 5. ビルド確認

```bash
npm run build
npm run preview
```

ビルド後の画面で、ローカル開発時と同じように動くことを確認する。

## プロジェクトの公開方法

公開先は **GitHub Pages** とする。

### 方針

- サーバを使わない
- APIサーバを立てない
- 到達圏データは事前計算済みの静的ファイルとして配信する
- GitHub Pages上では、HTML、CSS、JavaScript、GeoJSONのみを配信する

### 公開手順

1. GitHubにリポジトリを作成する
2. プロジェクト一式をpushする
3. GitHub ActionsまたはGitHub Pages設定で公開する
4. `npm run build` の出力先をGitHub Pagesに配信する
5. 公開URLで地図・イベント・到達圏が表示されることを確認する

### Viteを使う場合の注意

GitHub Pagesでは、`vite.config.js` に `base` を設定する必要がある場合がある。

例:

```javascript
export default {
  base: "/REPOSITORY_NAME/"
}
```

リポジトリ名が変わる場合は、この値も変更する。

## 実装方針

### MVPではr5pyを使う

ローカル環境でr5pyを使い、GTFSとOSMから到達圏を事前計算する。

計算結果はGeoJSONとして保存し、GitHub Pages上のアプリで読み込む。

### OTPは発展版として扱う

OpenTripPlannerはGBFSを含む本格的なマルチモーダル経路探索に向いている。  
ただし、サーバ運用が必要になるため、GitHub Pages公開を前提とするMVPでは常時稼働させない。

将来的な発展版として、以下を検討する。

- GTFS + OSM + GBFSをOTPに投入
- 公共交通 + レンタサイクルの実経路探索
- レンタサイクル在庫・返却可否を考慮
- イベント終了時刻から帰宅可能性を判定

## 最初に作るMVP

最初のMVPは、以下に絞る。

- 対象地域: 大阪市周辺
- 起点: 大阪駅、なんば駅、天王寺駅
- 時間帯: 休日昼
- 移動手段:
  - 公共交通のみ
  - 公共交通 + レンタサイクル
- 表示:
  - 到達圏ヒートマップ
  - イベントピン
  - 到達可能イベント数
  - レンタサイクル併用で増えたイベント数

## 審査向け説明文

「車なしイベントマップ」は、公共交通とレンタサイクルを組み合わせた到達圏を可視化し、地域イベントを地図上に重ねて表示するWebアプリです。公共交通を単なる移動手段ではなく、車を持たない人が地域活動に参加するためのインフラとして捉え、公共交通だけで行けるイベント、レンタサイクルを足せば行けるイベント、帰りが難しいイベントを直感的に示します。重い経路計算は事前に行い、GitHub Pagesで静的に公開できるため、自治体・市民開発者・個人でも低コストに運用できます。
